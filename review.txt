Blocking findings, severity ordered

1. [P1] Gate the shared event subscription for older daemons.
   packages/app/src/contexts/session-context.tsx:489
   The shared observeEvents call always includes agent_prompt_suggestions, even when the host lacks features.promptSuggestions. With an owned-subscription daemon from the base commit, the entire session.events.set_subscription.request fails enum validation at events[1]. This prevents the common feed from registering, including permission requests/resolutions and attention notifications. The feature gate in usePromptSuggestions protects only the dedicated suggestion RPC. Gate subscription membership too, restoring it when host features become known or change.
   Evidence: loaded the actual messages.ts from d6fa23189 and parsed the event list extracted from the head's SessionProvider: without the new event=true; with the new event=false; head schema=true. Base websocket-server.ts advertises ownedSubscriptions:true, so the legacy filter does not protect this supported combination. See handoffs/TH1-1798/review-inspect.log.

2. [P2] Reserve concurrency before asynchronous prompt preparation.
   packages/server/src/server/agent/prompt-suggestions/service.ts:440
   entry.generating and inFlight are set only after await preparePrompt (lines 457-458). While that awaits repository/config/context work, drain sees available capacity and requestFor sees an idle entry. A burst can start more metadata agents than maxConcurrent, including duplicate generation for the same agent. Separately, requestForDraft at line 221 calls generateDraft outside this queue, so draft requests also escape the limit. Reserve a slot and the per-agent running state before the first await, release both on every exit, and route drafts through the same budget.
   Evidence: one review-only test in the existing service.test.ts holds readWorkspaceContext pending, requests three agents with maxConcurrent=2, then releases it. Three provider calls start; expected <=2 fails. Run: cd packages/server && npx vitest run src/server/agent/prompt-suggestions/service.test.ts --bail=1 -t 'review: reserves concurrency slots'. Result: 1 failed, 30 skipped. Patch and real output are in handoffs/TH1-1798/review-reproduction.patch and review-vitest.log. The pre-existing cap test uses immediately resolved preparation, so it misses this suspension point. The added test was removed from the review checkout after preserving the patch; the PR branch was never edited.

3. [P2] Render a save error in the suggestion model settings.
   packages/app/src/screens/settings/suggestion-model-section.tsx:67
   A rejected patchConfig call clears draft mode and reports the error only through Alert.alert imported from react-native. React Native Web's Alert.alert is empty, so browser and Electron users see no error or retry explanation after a failed save. Use the app's rendered alert/error pattern and retain an actionable error in the section. This is required by docs/testing.md's fallible-user-actions contract. Static evidence: installed react-native-web/dist/exports/Alert/index.js defines static alert() {}. The new settings tests replace Alert with a spy and cover successful writes only; they do not establish visible failure feedback.
